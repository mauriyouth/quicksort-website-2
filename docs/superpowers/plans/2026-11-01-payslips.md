# Payslips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** HR drops Silae's monthly payslip PDFs into the admin. Each one is matched to its employee by matricule, filed in the person's HR Drive folder as a registered `PAYSLIP` document, and shown on the person's HR page and in the employee's own portal.

**Architecture:**
- Parsing happens **in the browser**. pdfjs-dist reads the text and fflate unzips. This matches the registry's existing pattern, where bytes go browser → Drive through `prepare-upload` and never pass through the serverless function (whose request limit is about 4.5 MB). It replaces the spec's "server-side" line: the HR operator is already trusted to file any document for any person, and every filing still goes through `register_document` and RLS.
- Matching is a pure function over the employees and payslips already loaded.
- The database gains:
  - the `PAYSLIP` type
  - matricule uniqueness per person
  - a `set_employee_matricule` RPC
  - a self-only `my_payslips` view
  - a `payslip_download_source` RPC for the portal download
- The documents API gains two actions: `download-own-payslip` (for any signed-in user) and `move-payslip` (for HR).

**Tech Stack:** React 18 + react-router 6 (apps/admin), Supabase Postgres (migrations, RLS, security-definer RPCs), node:test with `--experimental-strip-types` (tests/*.test.mjs), the SQL checks run by `pnpm test:hr-db` (Docker), pdfjs-dist, fflate, pdfmake (already a dependency; used to build synthetic test PDFs).

**Spec:** `docs/superpowers/specs/2026-11-01-payslips-design.md`

## Global Constraints

- Document type code: `PAYSLIP`; label `Bulletin de paie`; owner kind `person`; `requires_expiry = false`; `sensitive = true`; `required_for = '{}'`.
- Drive path: `<people root>/<NOM Prénom> – <id>/08_Bulletins_de_paie/<YYYY>/`, where YYYY is the payslip **period** year.
- Period is stored as `documents.valid_from = YYYY-MM-01`. The Silae index `n` and the content hash are stored in the existing `title` and `sha256` columns. The title format is `Bulletin de paie <Mois YYYY>` for `n = 1` and `Bulletin de paie <Mois YYYY> (n)` for `n > 1`.
- Matricule: two different people never share one. Rows of the same person may. New rows keep the `QS-0000` default.
- Never commit a real payslip. Test PDFs are generated with pdfmake using made-up names and numbers.
- Documents are never deleted. A wrong filing is moved, and the old record is set to `archived`.
- Import limits: PDFs only (`%PDF-` magic bytes), at most **200 files** per drop, **10 MB** per PDF, **100 MB** total uncompressed for a zip. Zip entry paths are reduced to their base name, and entries with `..` or absolute paths are ignored.
- Admin access to payslips is the same as the person's Documents section (`workspace.capabilities.recruit`, i.e. admin + hr). See the handoff note: the spec says "everyone who can see the HR page", which today also includes sales.

## Review Focus

1. **A second PDF in the same drop for the same person and period** (e.g. a `_1` and a `_2`): both are kept as separate rows. If it's the same `n` twice, the second is flagged "duplicate in this drop", not filed twice. *Test: Task 4.*
2. **A file name with accents, hyphens or several first names** (`ADOTRI_FRIMPONG_MALCOM_MICHEL-ANGE_10_2026_1.pdf`) still name-matches "Malcom Michel-Ange Adotri Frimpong". *Test: Task 4.*
3. **A matricule written without leading zeros in the admin** (`26`) matches Silae's `00026`. Comparison is on the digits with leading zeros stripped, and the stored value is the Silae form. *Test: Task 4.*
4. **A non-payslip PDF or a scanned PDF** (no text layer) is shown as "Unreadable" and never blocks the other files. *Test: Task 3.*
5. **An employee whose portal account is linked to a different person** can never list or download someone else's payslip, even by passing a known document id. *Test: Tasks 1 and 5.*

### Task 3: Reading a Silae drop (unzip, PDF text, parse)

**Files:**
- Modify: `apps/admin/package.json` (add `pdfjs-dist` 4.10.38 and `fflate` 0.8.2, pinned)
- Create: `apps/admin/src/payslips/parse.ts` (pure parsing, no DOM)

- Create: `tests/fixtures/payslips/make-payslip.mjs` (pdfmake generator for synthetic payslips)
- Test: `tests/payslip-parse.test.mjs`

**Interfaces:**
- Produces:
  - `type ParsedPayslip = { fileName: string; matricule: string; period: string /* YYYY-MM */; index: number; nameFromFile: string; sha256: string; bytes: Uint8Array }`
  - `type UnreadablePayslip = { fileName: string; error: string }`
  - `parsePayslipText(items: string[], fileName: string): Omit<ParsedPayslip, "sha256" | "bytes"> | { error: string }`
  - `readPayslipDrop(files: { name: string; bytes: Uint8Array }[]): Promise<(ParsedPayslip | UnreadablePayslip)[]>`
  - `payslipTitle(period: string, index: number): string`, e.g. `"Bulletin de paie Octobre 2026"` or `"… (2)"`.

Parsing rules, taken from the real Silae layout as checked on 2026-11-01. pdfjs `getTextContent()` items on page 1 include:
- `"Période :"`, then blank items, then `"Octobre 2026"`
- the label run `"Matricule :" "N° SS :" … "Convention collective :"`, then the values in the same order, with the matricule first.

The rules:
- **Matricule:** the first non-blank item after the `"Matricule :"` label that matches `/^\d{1,10}$/`. The SS number is 15 digits, so it never matches.
- **Period:** the first non-blank item after `"Période :"` that matches `/^(janvier|février|mars|avril|mai|juin|juillet|août|septembre|octobre|novembre|décembre) (\d{4})$/i`.
- **File name:** must match `/^(.+)_(\d{2})_(\d{4})_(\d+)\.pdf$/i`. Group 1 with `_` replaced by spaces is `nameFromFile`; group 4 is `index`.
- If the file-name month or year disagrees with the PDF period, return the error `Period in file name (MM/YYYY) differs from the payslip (Mois YYYY).`
- If there's no matricule or no period, return `Not a Silae payslip, or the PDF has no text.`

- [ ] **Step 1: Write the fixture generator `make-payslip.mjs`.** It exports `makePayslip({ name, matricule, periodLabel }) => Promise<Uint8Array>`. It builds a one-page pdfmake document with the label run, then the values in the same order (fake SS `199999999999999`, fake IBAN `FR76 0000`), and `Période :` followed by `periodLabel`.

### Task 4: Matching payslips to employees

**Files:**
- Create: `apps/admin/src/payslips/match.ts`
- Test: `tests/payslip-match.test.mjs`

**Interfaces:**
- Consumes: `ParsedPayslip`, `UnreadablePayslip` (Task 3).
- Produces:
  - `type MatchEmployee = { id: string; person_id: string; matricule: string; status: string; end_date: string | null; full_name: string }`
  - `type FiledPayslip = { id: string; person_id: string; valid_from: string; title: string; sha256: string | null }`
  - `type ReviewStatus = "matched" | "confirm" | "unknown" | "unreadable" | "already-filed" | "changed" | "duplicate"`
  - `type ReviewRow = { file: ParsedPayslip | UnreadablePayslip; status: ReviewStatus; personId: string | null; employeeIdForMatricule: string | null; supersedes: string | null; warning: string | null; printedName: string }`
  - `matchPayslips(files, employees: MatchEmployee[], filed: FiledPayslip[]): ReviewRow[]`
  - `normalizeName(s: string): string`: lowercases, strips accents, turns hyphens and underscores into spaces, sorts the words.
  - `sameMatricule(a: string, b: string): boolean`: compares digits only, with leading zeros stripped. Non-digit values must match exactly.

Rules (spec, "Import flow" step 3 and step 5):
- **Matched:** the matricule is held by exactly one person, and their normalized name equals or contains the normalized file name (or the reverse).
- **Confirm:**
  - The matricule is held, but the name disagrees. `warning` names both people.
  - No matricule is held, but exactly one person's name matches. `employeeIdForMatricule` is that person's open row, else their latest row by `start_date`. `warning` is set if that row already holds a non-`QS-` matricule different from the PDF's.
- **Unknown:** neither the matricule nor the name matches anyone, or the name matches several people.
- **Already filed:** a `filed` row exists for the same person, the same `valid_from` (`period-01`) and the same title, with an equal sha256.
- **Changed:** as above, but the sha256 differs. `supersedes` is that row's id.
- **Duplicate:** a second file in the drop with the same matricule, period and index.
